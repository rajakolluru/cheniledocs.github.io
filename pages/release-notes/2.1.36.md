# Chenile 2.1.36 <span class="pill">in development</span>

**Not released.** The train moved to 2.1.36 after 2.1.35 was tagged. These notes track work merged since then and
will change before the release.

## JGen and stm-cli have their own releases

Until now JGen and stm-cli shared Chenile's version number. From now on they are released on their own cadence,
and each is built only against Chenile versions that are already released.

- **JGen** continues at **2.5.1**. Everything added to JGen since 2.1.35 ships in JGen 2.5.1, not in Chenile 2.1.36:
  generated Git repositories, standalone blueprint projects, template-only blueprints, catalogs, JavaScript hooks,
  extensions (template engines including Pebble, language packs, path tags), `_DoT_` for dotfiles, and the
  `GITHUB_REPOSITORY` and `PATTERN` rules. Its libraries move to the Maven group `org.chenile.jgen`. See
  [JGen releases and versions](https://jgen.chenile.org/releases/).
- **stm-cli** starts its own line at **1.0.0** in its own repository,
  [rajakolluru/stm-cli](https://github.com/rajakolluru/stm-cli), and installs with
  `brew install ajapros/jgen-tap/stm-cli`.

## workflow-utils: the stm-cli command moved out

The command-line entry point `org.chenile.workflow.cli.CLI` (and its `VersionProvider`) moved to the stm-cli
project as `org.chenile.stmcli.StmCli`. workflow-utils no longer builds a `jar-with-dependencies`.

`CLIHelper` and `CLIParams` stay in workflow-utils, so code that renders diagrams or test cases from a states XML
is unaffected. That code includes workflow-info, stm-generate-puml and JGen.

If you ran `java -jar workflow-utils-<version>-jar-with-dependencies.jar`, install stm-cli instead.
