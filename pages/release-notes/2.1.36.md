# Chenile 2.1.36 <span class="pill">in development</span>

**Not released.** The train moved to 2.1.36 after 2.1.35 was tagged. These notes track work merged since then and
will change before the release. So far it is all JGen.

## JGen: new blueprints in their own Git repository

The `jgen-blueprint` blueprint has a new input, `standaloneRepo`. With `y` it generates a self-contained blueprint
project and makes it a local Git repository on branch `main` with one commit, ready to push. The project has its
own groupId and version, `jgen-base` as a provided dependency, a README, a `.gitignore` and a release workflow that
attaches the jar to a GitHub release for `jgen -g github:owner/repo`. JGen prints the remaining steps: create the
GitHub repository, add the remote, push, tag.

Every generated blueprint now also has a working starter template, a corrected init hook and a test that generates
from it.

Blueprints get a fifth hook point, `finalHook`. It runs last, after the generation record is written, and suits
work outside the file tree.

## JGen: `_DoT_` for dotfiles in templates

A new template convention: every `_DoT_` in a file or folder name becomes a dot, so `_DoT_gitignore` is generated
as `.gitignore` and `_DoT_github/workflows` as `.github/workflows`. Maven drops dotfiles from blueprint jars, so this
is how a blueprint ships them. It runs right after `__key__` placeholders (a new pipeline step, `dot-replacer`).
See the [template reference](https://jgen.chenile.org/template-conventions/).

## JGen: `GITHUB_REPOSITORY` and `PATTERN` validation rules

Two new input validation rules:

- **`GITHUB_REPOSITORY`** accepts `owner/repo` and follows GitHub's naming limits. The `jgen-blueprint` blueprint
  now uses it for `githubRepository`, instead of a check in its hook.
- **`PATTERN`** with `pattern` and `patternMessage` covers a format specific to one blueprint. The whole value must
  match, and the message is what users see. The pattern is checked when the blueprint loads.

Error messages for every rule now say what a valid value looks like. See
[input validation](https://jgen.chenile.org/input-validation/).

## JGen: generated projects as Git repositories

Any blueprint can now have JGen make its output a local Git repository, with no code:

- **Turning it on:** set the input `initGit` to true, either as a prompt or from a hook. JGen then runs `git init`
  on branch `main`, adds everything and makes one commit. This is a new pipeline step, `git-initializer`, which
  runs after the generation record is written.
- **Connecting to GitHub:** a blueprint that names a `GITHUB_REPOSITORY` input in its new `gitRepositoryField`
  property also gets that repository as the `origin` remote, ready to push.
- **Remote style:** SSH by default, or HTTPS when the config has `gitRemoteProtocol` set to `https`.
- **Commit message:** `gitCommitMessage` sets it.
- **What it never does:** create the GitHub repository or push.

`jgen-blueprint` now uses this feature for standalone blueprint projects.

## JGen: Homebrew installs find their Java

The Homebrew formula depends on `openjdk@25`, which Homebrew does not put on the PATH. In 2.1.35 the `jgen`
launcher only found Java through `JAVA_HOME` or the PATH. It now also looks in Homebrew's `openjdk@25` location, so
`brew install ajapros/jgen-tap/jgen` works on a machine with no other Java.
